# 🧠 ЯДРО СИСТЕМЫ (Scam Detection Engine)

## 🎯 Задача ядра

В реальном времени оценивать:

> развивается ли разговор по сценарию когнитивного давления (мошенничества) и насколько он опасен прямо сейчас.

---

# 📥 Вход в ядро

Ядро не получает “звонок”.

Оно получает поток событий:

## 1. 🗣 Текст речи (STT поток)

Разбитый на короткие сегменты:

```text
t+0s: "Здравствуйте, это служба безопасности банка"
t+3s: "у вас подозрительная операция"
t+7s: "нужно срочно подтвердить данные"
```

---

## 2. ⏱ Метаданные времени

* паузы
* скорость речи
* перекрытия
* длительность сегментов

---

## 3. 📊 Контекст разговора (история)

* что уже было сказано
* какие сигналы уже активировались
* текущий уровень риска

---

# 🧩 Внутренняя структура ядра

```text id="core1"
        [STT сегмент]
               ↓
     1. Feature extractor
               ↓
     2. Pattern detector (rules + embeddings)
               ↓
     3. Scenario model (LLM reasoning)
               ↓
     4. Risk aggregator
               ↓
     5. State machine (risk level over time)
```

---

# ⚙️ 1. Feature Extractor

Превращает текст в признаки:

## Из каждого сегмента:

* тип утверждения (вопрос / утверждение / приказ)
* наличие давления (“срочно”, “немедленно”)
* наличие авторитета (“банк”, “полиция”)
* наличие действия (“переведите”, “скажите код”)
* эмоциональный тон (страх/угроза)

---

👉 результат:

```json
{
  "urgency": 0.8,
  "authority": 0.9,
  "action_request": 0.3,
  "fear_signal": 0.7
}
```

---

# 🧠 2. Pattern Detector (быстрый слой)

Это НЕ LLM.

Это быстрый слой:

* правила
* embeddings similarity
* keyword + phrase patterns
* sequence detection

---

## Он ловит:

### 🔴 Сигналы:

* “банк + срочно + операция”
* “следователь + дело”
* “переведите деньги”
* “не сообщайте никому”

---

## Выдаёт:

```text
detected_patterns = [
  AUTHORITY_PLAY,
  URGENCY_ESCALATION,
  ISOLATION_SIGNAL
]
```

---

# 🧠 3. Scenario Model (LLM слой)

Вот здесь появляется “интеллект”.

LLM делает:

> интерпретацию структуры разговора

---

## Он отвечает на вопросы:

* Это похоже на известный сценарий атаки?
* Какой тип социальной инженерии развивается?
* Какая стадия атаки сейчас?

---

## Пример вывода:

```json
{
  "scenario": "bank_fraud_impersonation",
  "stage": "escalation",
  "confidence": 0.82
}
```

---

# 📊 4. Risk Aggregator

Объединяет всё:

* правила
* паттерны
* LLM вывод

---

## Формула (концептуально):

```text
risk = f(patterns, llm_confidence, urgency, authority, sequence_progression)
```

---

## Пример:

```json
{
  "risk_score": 0.87
}
```

---

# 🧠 5. State Machine (самое важное)

Это делает систему “живой”.

Риск не считается заново — он **накапливается во времени**.

---

## Состояния:

* SAFE
* MONITORING
* SUSPICIOUS
* HIGH_RISK
* CRITICAL

---

## Пример перехода:

```text
t+0s → SAFE
t+10s → MONITORING
t+25s → SUSPICIOUS
t+40s → HIGH_RISK
```

---

## Важно:

👉 один фрагмент НЕ решает всё
👉 решение = динамика разговора

---

# ⚡ Как ядро принимает решение

```text id="decision"
IF risk_score > threshold
AND escalation_detected
THEN trigger intervention
```

---

# 🚨 Выход ядра

Ядро НЕ “блокирует звонок”.

Оно выдаёт сигналы:

## 🟢 low

* ничего

## 🟡 medium

* мягкое предупреждение

## 🟠 high

* объяснение риска

## 🔴 critical

* срочный alert + доверенные лица

---

# 🧠 Ключевая идея ядра (самое важное)

> ядро не классифицирует “мошенник / не мошенник”,
> оно моделирует **эскалацию когнитивного давления во времени**

---

# 🔥 Почему это работает

Потому что мошенничество:

* не статично
* не зависит от слов
* всегда развивается как сценарий

---

# ⚖️ Итоговая формулировка ядра

> Real-time temporal risk engine that detects and tracks escalation patterns of social engineering in speech streams using hybrid rule-based and LLM-based reasoning.

---

# 🧭 Если совсем просто

Ядро делает 3 вещи:

1. слушает поток речи
2. понимает “что за сценарий развивается”
3. отслеживает, как быстро он становится опасным
