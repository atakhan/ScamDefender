# Сценарии и этапы скам атак

## 🧠 1. Базовая идея

Любой телефонный развод — это не “разговор”, а:

> последовательная эскалация управления поведением человека

---

## 📊 2. Универсальные стадии атаки (общие для всех сценариев)

Это каркас, который повторяется почти всегда:

---

### 🟢 STAGE 0 — Normal contact (вход)

* нейтральное начало
* представление
* проверка реакции

📌 пример:

> “Здравствуйте, это служба поддержки…”

---

### 🟡 STAGE 1 — Authority / Framing

Задаётся рамка доверия или страха:

* банк
* полиция
* госорган
* “безопасность”

📌 цель:

> создать легитимность

---

### 🟠 STAGE 2 — Problem injection

Вводится проблема:

* подозрительная операция
* взлом
* долг
* ошибка

📌 цель:

> создать эмоциональный дисбаланс

---

### 🔴 STAGE 3 — Pressure escalation

Начинается давление:

* срочно
* нельзя откладывать
* нельзя проверять

📌 ключ:

> ломается рациональная проверка

---

### 🔴 STAGE 4 — Control & isolation

Появляется контроль поведения:

* “не говорите никому”
* “следуйте инструкциям”
* “не кладите трубку”

📌 цель:

> отключить внешнюю валидацию

---

### 🚨 STAGE 5 — Action execution

Финальная стадия:

* перевод денег
* код из SMS
* установка приложения
* доступ к устройству

📌 это точка потери денег

---

### 🧠 STAGE 6 — Reinforcement / recovery

(не всегда)

* повтор давления
* закрепление контроля
* удержание жертвы

---

## ⚙️ 3. Теперь сценарии (типы атак)

Это “шаблоны поверх стадий”.

---

## 🏦 1. Bank impersonation scam

### Суть:

“мы из банка, у вас проблема”

### Типичный путь:

```text id="bank1"
STAGE 1 → банк / безопасность
STAGE 2 → подозрительная операция
STAGE 3 → срочно
STAGE 4 → не сообщайте никому
STAGE 5 → переведите деньги / код
```

---

## 👮 2. Law enforcement scam

### Суть:

“следователь / полиция / уголовное дело”

### Особенность:

максимальное давление страхом

```text id="police1"
STAGE 1 → авторитет (полиция)
STAGE 2 → уголовное дело
STAGE 3 → срочно явиться / сотрудничать
STAGE 4 → секретность
STAGE 5 → переводы / данные
```

---

## 👨‍👩‍👧 3. Family emergency scam

### Суть:

“ваш родственник в опасности”

### Особенность:

эмоциональный шок

```text id="family1"
STAGE 2 → угроза близким
STAGE 3 → срочно помочь
STAGE 4 → не звонить ему
STAGE 5 → деньги / курьер
```

---

## 💳 4. Financial transfer scam

### Суть:

“спасите деньги / безопасный счёт”

```text id="finance1"
STAGE 1 → банк/служба
STAGE 2 → риск потери денег
STAGE 3 → срочно перевести
STAGE 4 → не сообщать
STAGE 5 → перевод
```

---

## 📲 5. Device takeover scam

### Суть:

“установите приложение / доступ к устройству”

```text id="device1"
STAGE 1 → техподдержка
STAGE 2 → проблема с аккаунтом
STAGE 3 → срочная установка
STAGE 5 → удалённый доступ
```

---

## 📦 6. Delivery / marketplace scam

### Суть:

“посылка / доставка / подтверждение”

```text id="delivery1"
STAGE 2 → проблема с доставкой
STAGE 3 → срочно подтвердить
STAGE 5 → код / данные / оплата
```

---

## 🧠 4. Как это используется ядром

Теперь самое важное.

---

### Ядро НЕ пытается “угадать мошенника”

Оно делает 3 вещи:

---

#### 1. Определяет текущую стадию

```json id="stage"
{
  "stage": "STAGE_3",
  "confidence": 0.78
}
```

---

#### 2. Определяет сценарий

```json id="scenario"
{
  "scenario": "bank_impersonation",
  "confidence": 0.82
}
```

---

#### 3. Отслеживает эскалацию

```text id="trend"
SAFE → MONITORING → SUSPICIOUS → HIGH_RISK
```

---

## ⚡ 5. Главный инсайт (самый важный)

Решение принимается НЕ по словам.

А по:

> переходу по стадиям + ускорению давления

---

## 🔥 6. Что делает систему сильной

Даже если:

* STT ошибается
* слова разные
* мошенники меняют формулировки

👉 стадии остаются одинаковыми

---

## 🧠 Финальная формулировка онтологии

> Telephone scam detection is a temporal classification problem over staged social engineering escalation patterns, not a static text classification task.
